# 建功高中巡堂點名

老師依考程選班、登記異常後確認全班。管理者匯入標準 Excel、開放或結案考試，並匯出學生總表與逐筆明細。

## 分開匯入與年度資料

- 年度學生名單與教室配置分開匯入，各有獨立的單張工作表 Excel 範本、下載及搜尋功能。年級欄國一至國三為1至3，高一至高三為4至6。
- 可在年度名單更正姓名；教室配置可微調樓層、位置說明及核對狀態。姓名依學號同步顯示於所有既有考試；教室描述依相同代碼與名稱同步。各次考試的班級、座號、應試安排與已存出席紀錄保留。
- 後台按「新增考試」，在網站填考試名稱並匯入考程，伺服器預覽時自動產生唯一考試代碼，確認時沿用同一代碼。沿用年度資料建立「準備中」考試並自動選取。再獨立匯入應試安排，確認後開放點名；開放後不可覆蓋應試安排。無特殊安排可直接開放。
- 空白考程範本不含考試名稱與考試代碼；舊格式仍支援，新增時以網站設定取代舊檔的名稱與代碼。「目前管理考試」只選擇既有考試；重匯簡化考程沿用目前考試身分，若舊檔帶有不同的考試代碼則拒絕匯入。
- 既有考試可由管理者「沿用年度資料」初始化共用名單與教室配置，此操作只補建缺少的年度資料。
- 老師直接選國一、國二、國三、高一、高二或高三，記住上次年級並只顯示該年級班級。依各班考程顯示目前或下一場，亦可搜尋班級。手動時段以所選年級的實際時間區間呈現，跨節考試在涵蓋的區間都可找到，但保存及報表仍只有一個場次。
- 管理者可重設單班場次或整次考試。重設清除目前確認結果與備註、恢復未點名／抽離／免到考預設，保留歷次稽核紀錄，報表顯示未確認。版本檢查防止重設時覆蓋剛送出的新紀錄；重設後老師需重新進入。結案後需先重新開放才能重設。

## 使用規則

- 新場次帶入同一天、同班最近一場已確認考試的出席／缺席，僅在該場尚無紀錄時套用。當場抽離及免到考優先，不帶入前場備註、抽離、免到考或舊遲到；仍須老師確認才儲存。已儲存或管理者重設的場次不自動覆蓋，查看或匯出也不會替未確認場次建立紀錄。
- 請假統一視為缺席；既有請假在點名、總覽、修改紀錄與報表統一顯示缺席，底層原始稽核資料保留。
- 老師首頁以找班與點名為主，不顯示整體完成量。管理後台提供日期、年級、班級篩選總覽，可查看未確認、有缺席場次與填寫者，每 20 秒更新。
- 學生姓名顯示中間遮蔽，管理者更正姓名及匯出保留原名。

- 開放前檢查總覽：選擇應考年級，依年度及考試名單核對缺班與各日考程，集中列出格式、時間重疊、學號／場次／抽離地點問題。資料錯誤禁止開放；缺班或位置提醒需人工確認。檢查綁定考程與年度資料版本，資料改動後需重新檢查。此檢查不代替核定考程的科目核對。
- 考試選單預設收合已結案、或考程結束超過30天的歷史考試（準備中考試保留）。展開歷史清單可搜尋、選取後匯出或複製，僅影響清單呈現，不刪除或鎖定資料。
- 「複製考程建立新考試」指定新名稱與每個原考試日的新日期，預覽確認後以新代碼建立準備中考試。使用當前年度學生及教室資料；不複製應試安排、點名、備註或稽核紀錄。來源考程或年度資料在預覽後變動會拒絕建立，需重新預覽。

- 管理後台的「每次考試」提供「修改考試名稱」，準備中、開放中及已結案考試皆可修改。同步更新入口、考程與報表名稱，保留考試代碼、考程時段、應試安排、點名紀錄與老師登入；同時修改時檢查原名稱與資料版本以避免覆蓋。

- 老師選擇開放中的考試並填寫姓名即可開始點名，無需通行碼，登入有效 12 小時；管理者密碼登入有效 4 小時。
- 未點名學生在確認全班後轉為出席；抽離為初始安排，可依現場更正；免到考保留固定安排。自習不點名，跨節考試只記一次。
- 抽離不代表已在另一考場報到，報表另列是否已確認。
- 同班同場採版本檢查，衝突時需重新載入核對。連線失敗保留本頁修改，尚未儲存的資料不保證跨重新整理保留。
- 開始點名或結案後不得覆蓋名冊。新考試使用新的考試代碼。
- 結案會使既有老師登入失效。管理者重新開放後，老師需重新進入。
- 管理後台可修改管理者密碼：輸入目前密碼、新密碼與確認密碼（4至200個字元）。修改後所有管理者登入失效，需使用新密碼重新登入；老師登入不受影響。
- 老師入口不核實身分；任何取得網址的人可填寫姓名查看開放考試的學生資料與登記出席，姓名僅為操作紀錄。匯入、匯出及設定仍限管理者。

## 資料與部署

私人 GitHub 儲存庫僅保存程式、空白匯入範本、合成測試資料與資料庫結構。學生資料、密碼、點名紀錄和匯出檔不得提交。

網站部署於 GPT Sites（Cloudflare Workers + D1）。學生資料透過管理者登入後的匯入功能寫入 D1，不包含於程式或公開資產。前台公開入口；老師填寫姓名後建立限於單次考試的工作階段，管理操作仍由伺服器檢查管理者權限。

環境變數 ADMIN_PASSWORD_HASH 為初始管理密碼，使用 100000 次 PBKDF2-SHA256 的 salt:hash（salt 為 16 bytes 的 hex 字串，以 UTF-8 參與衍生）；SITE_ORIGIN 為正式網址。後台修改密碼後，D1 的 admin_credentials 雜湊與版本優先，不需重新部署，後續發布也不會還原密碼。不得提交實際值。既有 code_hash 欄位僅為資料庫相容保留，不再參與驗證；code_version 用於考試結案、重新開放及替換名單時撤銷舊老師工作階段。

## 開發與驗證

GitHub Actions 自動回歸測試會在 PR 與 main 更新時執行型別檢查、規則／姓名遮罩測試、
正式建置及隔離本機 D1 API 測試。執行方式、日誌與驗證邊界見 [tests/README.md](tests/README.md)。
CI 不部署網站，也不取代正式環境驗收。

Node.js >= 22.13，pnpm 11。執行 pnpm install、pnpm build。開發預覽為 pnpm dev。透過 Sites 外掛的標準流程打包及發布，不使用 GitHub Pages。

- 型別檢查：pnpm typecheck
- 規則與姓名遮罩測試：pnpm test:unit
- 隔離 API 回歸：pnpm build && pnpm test:api（每組使用全新本機 D1 與合成資料）
- API 測試：node tests/api.mjs（僅允許 localhost，使用 TEST_ADMIN_PASSWORD 環境變數或測試專用預設密碼；會建立合成測試考試）
- 同日帶入與確認邊界測試：node tests/carry-forward.mjs（僅限本機）。
- 資料與重設測試：node tests/admin-data.mjs（僅限本機，更新合成年度資料並建立測試考試）。時段與同步規則：node --experimental-strip-types --test tests/patrol-view.test.ts。
- 本機資料表：先 build 產出 dist/server/wrangler.json，再執行 node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_outgoing_lizard.sql。只對未套用的 migration 執行一次。
- 正式 schema 由 Sites 部署流程套用。程式發布不搬移本機測試資料。

匯出報表應由管理者另行保存備份。網站不是學籍主檔，原始名單及核准考程仍應由校方保存。
